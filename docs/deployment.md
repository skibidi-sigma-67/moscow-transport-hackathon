# Руководство по развертыванию и запуску

Данный документ описывает процесс полного развертывания программно-аппаратного комплекса предиктивной аналитики.

## Требования к окружению
- Установленный Docker (v24.0+)
- Установленный Docker Compose (v2.0+)
- Доступ к интернету для загрузки базовых образов и зависимостей

## Шаг 1: Подготовка исходного кода

Склонируйте репозиторий проекта на целевой сервер или локальную машину:

```bash
git clone <repository_url>
cd moscow-transport-hackathon
```

## Шаг 2: Настройка переменных окружения

Для работы системы требуется конфигурационный файл `.env`. 
В корне репозитория находится шаблон `.env.example`. Скопируйте его и задайте необходимые значения:

```bash
cp .env.example .env
```

### Настройка Yandex Maps API
Для корректной работы Frontend-приложения и отображения интерактивной карты необходимо добавить ключ API Яндекс.Карт. 
Откройте созданный файл `.env` любым текстовым редактором и установите значение переменной:

```env
VITE_YANDEX_MAPS_API_KEY=ваш_ключ_api_яндекс_карт
```

Остальные параметры (доступы к базе данных, настройки портов) настроены по умолчанию для быстрого старта и могут быть изменены при необходимости.

## Шаг 3: Развертывание контейнеров

Запустите оркестрацию микросервисов с помощью Docker Compose в фоновом режиме:

```bash
docker compose up -d --build
```

Первый запуск может занять несколько минут, так как происходит сборка образов Backend, Machine Learning модуля, базы данных PostgreSQL и Frontend интерфейса.

## Шаг 4: Проверка работоспособности

После успешной сборки и запуска контейнеров сервисы будут доступны по следующим адресам:

1. **Информационная панель (Dashboard)** — Основной интерфейс комплекса доступен по порту 80:
   👉 `http://localhost`
   *(Здесь отображается карта, транспортные средства и выявленные инциденты)*

2. **API Backend (Управляющий сервис)** — Swagger UI:
   👉 `http://localhost:8000/docs`

3. **ML API (Предиктор)** — Swagger UI:
   👉 `http://localhost:8001/docs`

## Остановка системы

Для остановки всех работающих сервисов комплекса без удаления данных выполните:

```bash
docker compose stop
```

Для полного удаления контейнеров и сетей (осторожно: это не удалит тома (volumes) с базой данных, если они были настроены):

```bash
docker compose down
```
