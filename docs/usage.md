# Инструкция по использованию

Этот документ описывает основные сценарии работы с системой: от подключения потоков телеметрии до загрузки статического расписания.

## 1. Подключение потока NDTP

Телеметрические данные о движении транспортных средств поступают в систему в бинарном формате по протоколу **NDTP**.
Специальный TCP-сервер слушает входящие соединения.

**Куда направлять данные:**
Вам нужно настроить бортовые блоки или эмулятор на отправку TCP-пакетов по адресу развернутого Backend-сервиса.
- **IP / Хост**: IP-адрес машины, на которой запущен Docker Compose. (Если локально, то `127.0.0.1` или `localhost`)
- **Порт**: По умолчанию это `9201` (определяется переменной `BACKEND_NDTP_PORT` в `.env`).

*При успешном подключении в логах backend-сервиса начнут появляться сообщения об успешном парсинге NPH-SRV / NPH-SED пакетов, а транспортные средства мгновенно появятся на карте Dashboard.*

## 2. Загрузка статических данных (Расписание и связи)

Для того чтобы система могла находить отклонения от планового движения, необходимо загрузить:
1. **Расписание (`schedule.csv`)** — время прибытия транспорта на остановки.
2. **Связи (mapping)** — если применимо, связки `tr_id` (идентификатор трекера) с плановыми рейсами.

**Как загрузить файлы:**
1. Откройте главную страницу дашборда: `http://localhost` (или по вашему домену).
2. В интерфейсе найдите блок загрузки файлов (обычно расположен на панели управления или в модальном окне).
3. Выберите файл `.csv` с расписанием и нажмите кнопку загрузки.
4. Дождитесь уведомления об успешной обработке. Даты расписания автоматически адаптируются под текущий день (согласно логике приложения), поэтому вам не нужно вручную сдвигать исторические данные расписания в Excel/Python перед загрузкой!

После успешной загрузки расписания система сопоставит его с поступающей NDTP-телеметрией и начнет отправлять данные в ML-модуль для предсказания инцидентов.

## 3. Изменение параметров системы

Гибкость системы обеспечивается за счет конфигурации через переменные окружения. Все основные настройки вынесены в файл `.env`.

**Примеры параметров, которые можно менять:**
- `BACKEND_ML_TELEMETRY_WINDOW_MINUTES` — размер временного окна истории движения, которое передается в ML.
- `BACKEND_STOP_SPEED_THRESHOLD_KMH` — порог скорости (км/ч), ниже которого считается, что транспорт остановился (например, в пробке).
- `ML_WORKERS` — количество воркеров для обработки ML-запросов под высокой нагрузкой.
- Настройки базы данных (логин, пароль, порт).

**Как применить изменения:**
1. Откройте файл `.env` и отредактируйте нужные значения.
2. Перезапустите контейнеры, чтобы новые настройки вступили в силу:
   ```bash
   docker compose down
   docker compose up -d --build
   ```

## 4. Мониторинг инцидентов

После того как телеметрия поступает, а расписание загружено, на информационной панели (`http://localhost`) автоматически начнут появляться "инциденты" — ситуации, когда ML-модель предсказывает существенную задержку.
- **Цветовая индикация на карте**: Зеленый (по расписанию), Желтый (небольшая задержка), Красный (критическая задержка).
- Вы можете кликнуть на транспортное средство, чтобы посмотреть детальную аналитику: прогнозируемое отклонение в секундах, среднюю скорость сегмента и время простоя.
